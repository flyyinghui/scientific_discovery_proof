## 二、表演性诚实审计（P1 级缺陷，Stage 3.5 六类之外）

CGICE 交叉校核（2026-08-21）发现的一类缺陷——公理/前提**声明存在但无实质数学内容**，比可见 sorry 更危险（虚假的"已验证"信心）。四种子型：

1. **重言式公理**：`axiom a : (35:ℝ) ≤ 35` / `axiom b : (0:ℝ) ≤ 1` / `axiom c : (1:ℝ) = 1` — 恒真、零数学内容、且不被任何定理引用（装饰性死公理）。
2. **假全称公理**：`axiom d : ∀ (a b : ℝ), 0 ≤ a - b` — 取 a=0,b=1 即假，比重言式更糟（不一致公理，会让整个文件不可信）。
3. **零内容 def**：`def a1 : ℝ → ℝ := fun x => x`（恒等函数）— 声称编码流形但实际无内容。
4. **装饰性死公理**：研究级前提声明了，但 s* 定理根本不引用（只用 h_double=|ρ|²=35 和 hT6_ratio=3λ_⊥=|ρ|² 两个前提）。

**检测**：grep 活跃（非注释）的 axiom/def，找 `(N:ℝ) ≤ N` / `(N:ℝ) = N` / `fun x => x` / `∀ ... 0 ≤ a - b` 模式。

**修复法**（保持诚实 + 不破坏计数）：
- 重言式 → 实质编码（引用真实量）：`a_t3 : (35:ℝ) = rho_sq_doubled`（Harish-Chandra 下界=加倍 Weyl 范数）；`a_t4 : spec_gap_bound`（束缚条件成立）；`a_t5 : lam1 = 35/3`（首激发=横向谱隙）。
- 假全称 → `axiom spec_gap_bound : Prop`（研究级前提，非对任意实数的普遍断言）。
- 零内容 def → `def a1 : ℕ := 35`（编码流形维数）。
- 死公理 → 删除或标注"研究级前提，完整形式化待 Mathlib 流形库"。
