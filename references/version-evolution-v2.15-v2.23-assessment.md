## 二、形式化证明效率提升（用数据）

### 2.1 引理检索：recall@10 从 0.3225 → 0.5505（+71%）

v2.23.0 接入在 openai_math Lean 证明依赖对上全参微调的 `embeddinggemma-2-740m` 引理检索模型，为 PPE-V5.1Hybrid 的 MCTS/ABC 证明搜索提供「给定定理 → 候选引理/定义」召回。这是**可验证的真实测量**：

| 口径 | recall@10 | 相对基座提升 |
|---|---|---|
| 基座（未微调 embeddinggemma-2） | 0.3225 | — |
| 纯名字口径 | 0.4663 | +44.6% |
| **增强文本口径（名字词化 + 类型签名 120 + docstring 60）** | **0.5505** | **+70.7%** |

- 微调数据：openai_math Lean 依赖对 **377,098 对**（→ 双命中 349,234）
- 微调方式：全参微调，MNRL（MultipleNegativesRankingLoss），batch 256，2 epochs
- 声明库：从 openai_math 150,912 个 .lean 文件重新解析 `declarations.jsonl`

**效率意义**：MCTS/ABC 证明搜索的瓶颈在「每步展开需要大量候选引理，逐个尝试编译成本高」。retriever 把「盲搜候选引理」压缩为「top-10 召回」，直接降低搜索分支因子。**但诚实边界**：0.5505 是离线同分布指标，真实证明搜索收益未验证（需接入 Stage 3 跑实际任务对比）；本机编码 ~72 条/s，185 万声明全量索引 ≈7 小时，实际按需编码子集（秒级）。

### 2.2 世界模型预筛：省去「预测无增益」的 LLM 变异 + 编译

v2.21.0（JANUS）在昂贵的 LLM 变异 + Lean 编译之前，用 `archive.jsonl` 历史统计预测 (strategy × condition) 变异的期望增益 + 0-sorry 概率，预测无增益则 **PRUNE**（跳过本次变异省成本）。

- JANUS 论文报告 **3.74× 样本效率加速**（vs Codex，实验计数口径）
- 本落地世界模型是**纯历史统计 O(archive 大小)，毫秒级**，远快于 LLM 变异 + Lean 编译（秒~分钟级），满足「世界模型必须比编译快一个数量级」的移植约束

**效率意义**：进化循环的成本大头是「每代对每个候选跑 LLM 变异 + Lean 编译」。世界模型在变异前预筛，把「注定失败的变异」拦在编译前。

### 2.3 重放模拟器 + 策略元优化（v2.7 / v2.12，区间外但构成效率底座）

- v2.7.0 Dream-RSI 重放模拟器：`archive.jsonl` 从「被动记录」→「主动重放预筛选器」，ε-greedy 按历史成功率排序推荐变异策略（针对性是硬门槛）
- v2.12.0 策略元优化器：把「证明策略」（5 个变异策略权重 / 并行度 W / 放弃阈值 / 探索率 ε）编码为可执行 `ProofPolicy`，用历史重放反馈迭代改进策略参数本身（P3 单调性保证）

## 三、形式化证明准确性提升（用数据）

### 3.1 物理内容审计门控（v2.15）：把「0 sorry」与「物理非平凡」分开

这是区间内**最关键的准确性提升**，直接来自 V64 教训——「把物理对象定义为 S ≡ 谱底·‖φ‖²+V_top，则 bound 变重言式（35x+b ≥ 35x+b），是替换非推导，4/5 代理一致 P0」。

`physical_content_audit.py` 三类检测：
1. **字面恒等重言式**（conclusion 形如 X=X / X≥X / X≤X）→ BLOCK
2. **定义重言式**（rw/unfold 展开 conclusion 里的定义 + 无实质 tactic）→ BLOCK
3. **浅层证明**（无 calc/have/ring/exact 等实质 tactic）→ WARN

已接入 Stage 3.5b 主流程，任一 BLOCK 阻止 Stage 4 论文生成。

### 3.2 缺陷检测从 3 类 → 11+ 类（v2.15 + v2.16 累积）

v2.16.0 补齐 8 类盲区：参数化伪装（结论自由参数被赋值观测常量）/ 状态升级（theorem 含 sorry 被引用）/ 循环定义 / 假实数等式 / 孤立公理 / 换名复发 / import ghost 属性 / 嵌套注释 sorry 假阳性。每条含触发条件 + 反触发条件 + P0-P3 分级判据。

### 3.3 忠实性审计（v2.18 + v2.19）：把 V64 教训前移到「猜想定义时」

- v2.18.0 read-back 盲读回：两阶段（盲读只给 Lean 代码 → 对比 read-back vs 猜想意图），检测 formalization 忠实性 gap
- v2.19.0 Target 强度分层：目标应为最弱稳定陈述（真相形状）而非硬编码常数，一句话排除 vacuous hypothesis / trivial-true definition / hard-coded special case
- v2.19.0 disproof 反证分支：Stage 2 后主动尝试证明猜想否定，disproved → WARN 提示猜想可能为假

### 3.4 引用语义核查（v2.17）：幻影引用检测

在 reference_verification.py 的编号层核对之上，加 embedding 语义匹配层（引用上下文 vs 文献条目余弦相似度），用相对离群（Tukey 下界）而非绝对阈值检测疑似幻影引用。

## 四、RSI 自我进化环节（重点，v2.20.0 AIDE²/RSI）

### 4.1 来源与动机

AIDE²（Weco AI《Recursive Self-Improvement of AI Research Agents》，2026-09-22）是**第一个「净正递归自我改进」（RSI Level 1）的实验证据**：
- 双层架构（外层 agent 优化内层 agent 代码），~10% 接受率
- 8 天 100 步产出 7 个连续改进版本
- 泛化到 3 个外部基准打败 2 年手调基线
- **reward-hacking 率从 63% 自发降到 34%**

### 4.2 三项增量落地（对齐 AIDE² 未覆盖的缺口）

v2.19.0 已集成的 8 个框架覆盖 AIDE² ~80% 机制（双层 RSI=RSIHub、冻结评估器=RSIHub、严格门控=RSIHub、防 reward-hack=RSIAgent、失败路径=Colosseum、重放历史=Dream-RSI、策略元优化=Dream-RSI）。v2.20.0 补齐最后 3 项：

| 增量 | 落地 | 数据/机制 |
|---|---|---|
| **P0-① RSI 等级评估** | `stage36_evolution.py` 新增 `assess_rsi_level` | Level 0 委托（无净正增益）/ Level 1 净正（best>seed）/ Level 2 点火（ignition 诊断）/ Level 3 拐点（永不声称）；量化接受率 `acceptance_rate = n_accepted/n_total`（AIDE² ~10% 对等指标） |
| **P0-② 点火测试** | 新 `scripts/ignition_test.py` | 读 archive.jsonl，按 generation 分前/后两半比较接受率 + 平均 gain；后期接受率显著高（≥15pp）或后期 gain 显著高（≥5 分）→ 点火弱信号 |
| **P1-③ 隐藏评分机制** | `stage36_evolution.py` gate 阶段 | 双通道：可见分数（编译 0 sorry）+ 隐藏分数（physical_content_audit 的 BLOCK 数）；只在可见分数提高时才跑隐藏审计，物理内容零重言式才通过 |

### 4.3 RSI 环节的进步性评估（诚实分层）

**「进化循环」本身在 v2.4.0 已落地**（RSIHub 冻结评估器：select→evaluate→analyze→mutate→gate→record，MathCode 确定性评分 + DeepSeek v4-pro 诊断 + deepseek-flash 修复 + 严格改进门控 + append-only archive.jsonl）。v2.20.0 的增量是给它加上**自我评估的元层**：

1. **RSI 等级评估 = 诚实标注机制**：让进化循环能说出自己处于 AIDE² 哪个阶梯（Level 0/1），而不是笼统声称「在自我进化」。这与「预测度会计」方法论一致——防止把「净正改进」误标为「点火/智能爆炸」。
2. **点火测试 = 趋势诊断**：接受率趋势是「改进自身改进能力」的弱代理（AIDE² 的点火测试本身也「不明确」，统计不显著），本脚本诚实标注为「弱信号」。
3. **隐藏评分 = 事前预防**：把 reward-hack 的防线从「可见分数」前移到「隐藏的物理内容非平凡门槛」，AIDE² 借此把 reward-hacking 从 63%→34%。

### 4.4 RSI 环节的诚实边界（关键）

- **本机无真实进化数据**：P620（4GB）无法重跑完整 pipeline 求真实证明成功率，所有脚本的 `--dry-run`/`--self-test` 只验证机制不产出真实进化数据。真实优劣区分需 RTX4000 重跑。
- **RSI Level 2/3 永不声称**：本落地诚实标注只区分 Level 0/1，Level 2 由 ignition_test 诊断（且默认 inconclusive），Level 3（拐点/智能爆炸）永不声称。
- **世界模型（v2.21）不替代冻结评估器**：PRUNE 只跳过变异，幸存者仍走冻结评估器 + 隐藏物理内容审计定最终分数。

## 六、进步性总评

### 6.1 进步性判定

V2.15 → V2.23 这 9 个版本，是 scientific-discovery-proof 从「**能把证明跑通**」到「**能分辨证明是真还是假**」的质变期：

- **V2.15 之前**：管线能产出「0 sorry / 0 axiom 编译通过」的证明，但无法区分「实质证明」与「定义重言式」——V64 教训证明「0 sorry 编译通过 ≠ 物理推导成立」。
- **V2.15 之后**：物理内容审计门控（v2.15）+ 8 类缺陷（v2.16）+ 忠实性前置（v2.18/19）+ RSI 自我评估（v2.20）+ 世界模型预筛（v2.21）+ 幽灵子系统修复（v2.22）+ 引理检索（v2.23），把「证明质量」从「编译通过」的单一维度，扩展为「非平凡性 / 忠实性 / 引用真实性 / 进化净增益」的多维体系。

### 6.2 效率 vs 准确性（两条主线）

| 主线 | 代表版本 | 数据信号 |
|---|---|---|
| **效率**（降低证明搜索成本） | v2.21 世界模型 / v2.23 引理检索 / v2.7+v2.12 重放+策略元优化 | recall@10 +71%；3.74× 样本效率；毫秒级预筛 |
| **准确性**（分辨真假证明） | v2.15 物理内容审计 / v2.16 缺陷检测 / v2.18+19 忠实性 / v2.20 隐藏评分 | reward-hacking −29pp；缺陷类别 3→11+；隐藏物理内容门槛 |

### 6.3 RSI 自我进化环节的定位

v2.20.0 的 RSI 环节**不是新增一个「会自我进化的引擎」**（那个引擎在 v2.4.0 已落地），而是给它装上**诚实的自我评估仪表盘**：能说出自己处于 RSI 哪个阶梯、能否检测「改进自身改进能力」的点火信号、能否用隐藏物理内容标准防 reward-hack。这符合用户一贯的「诚实降级」方法论——**不声称点火/智能爆炸，只诚实标注 Level 0/1，把 Level 2 交给趋势诊断，Level 3 永不声称**。

### 6.4 最大遗留风险（诚实声明）

1. **无真实端到端进化数据**：本机 P620 只能跑 `--dry-run` 自测，所有机制落地但「从 conjecture 到 0 sorry 证明」的真实成功率、真实时间缩减、真实进化增益均未在本机测得，需 RTX4000 重跑验证。
2. **引理检索跨库迁移未测**：recall@10=0.5505 是 openai_math 同分布指标，迁移到 Mathlib/自制定理命名风格未验证。
3. **世界模型的 3.74× 是论文报告**：非本机复现，本落地版本的世界模型省成本量需实际运行确认。

## 七、结论

**V2.15 → V2.23 的 9 个版本，是 scientific-discovery-proof 从「证明生成工具」进化为「证明质量保障体系」的关键期。** 形式化证明的效率提升（引理检索 +71%、世界模型预筛）与准确性提升（物理内容门控、缺陷检测 3→11 类、忠实性审计、隐藏评分）双线并进；RSI 自我进化环节（v2.20）的价值不在于「制造智能爆炸」，而在于**诚实地度量自我改进能力**——这与整个 SL(6,C) 六篇论文的「诚实降级」方法论一脉相承。

**一句话总结**：这 9 个版本把「0 sorry」从一个容易被伪造的终点，变成了一个需要通过物理内容、忠实性、引用真实性、进化净增益四重门控才能真正抵达的诚实终点。
